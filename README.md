# BranchLab

Git のコマンドを入力すると、コミットグラフがアニメーションで変化する学習用の Web アプリです。
「ブランチを切る」「マージする」といった操作で履歴がどう変わるかを、実際に手を動かして確認できます。

## 使い方

```bash
npm install
npm run dev      # 開発サーバーを起動
npm test         # テストを実行
npm run build    # 型チェックと本番ビルド
```

## 対応コマンド

| コマンド | 内容 |
| --- | --- |
| `commit [-m "メッセージ"]` | 現在のブランチにコミットを追加する |
| `branch <名前>` | 現在のコミットから新しいブランチを作る |
| `switch <名前>` | ブランチを切り替える |
| `switch -c <名前>` | ブランチを作って切り替える |
| `merge <名前>` | ブランチをマージする (fast-forward またはマージコミット) |
| `reset [--soft \| --mixed \| --hard] [<コミット>]` | 現在のブランチを指定したコミットに移動する (既定は `--mixed`) |
| `help` | コマンド一覧を表示する |

先頭の `git` は省略できます (`git commit` も `commit` も同じ動作です)。

`<コミット>` には `C1` のようなコミット ID、ブランチ名、`HEAD` が使えます。
末尾に `~n` (第 1 親を n 回たどる) や `^n` (n 番目の親) を付けられます (例: `HEAD~2`, `main^`, `HEAD^2`)。

`reset` でどのブランチからもたどれなくなったコミットは、グラフ上に薄く残ります。
コミット ID を指定して `reset C3` のように戻ることもできます。
作業ディレクトリとステージはまだ表示していないため、現時点では 3 つのモードの違いはメッセージで説明するだけです。

## 設計

UI と Git の仕組みを分離しています。

```
src/
  git/
    model.ts       Git の内部モデル (コミットの DAG・ブランチ・HEAD)。純粋関数のみ
    commands.ts    入力文字列の解析と実行。規則違反は例外にせず結果として返す
  graph/
    layout.ts      Repo からコミットグラフの座標を計算する純粋関数
  components/
    GraphView.tsx  SVG によるグラフ描画とアニメーション
    Terminal.tsx   コマンド入力欄、実行ログ、サンプルコマンド
  App.tsx          状態 (Repo と実行ログ) の管理
```

- `Repo` は不変データで、すべての操作が新しい `Repo` を返します。そのためテストしやすく、
  「リセット」や将来の「元に戻す」も簡単に実装できます。
- レイアウトも純粋関数なので、描画せずに座標をテストできます。
